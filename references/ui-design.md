# UI 设计与验收

## 默认审美与验收门槛

默认简洁、现代、有自身风格；具体品牌、游戏主题和用户明确方向优先。这是设计目标，不是固定白底、无衬线、圆角卡片和浅色配色套餐，也不能保证任何模型一次生成就达到目标。

| 维度 | 判断依据 |
| --- | --- |
| 简洁 | 元素职责清楚，删去重复操作和无关装饰；信息密集也可以简洁，不靠删功能或放大空白达成 |
| 现代 | 字体比例、字重、间距、图标与控件精确协调，表面层级清楚；仅切换深色或增加渐变不构成改进 |
| 自身风格 | 选定的排版、构图、颜色语义或图像方式贯穿页面；能指出具体设计决定，不只说“高级” |
| 适合产品 | 焦点来自用户最重要的判断和行动；视觉表达加强业务关系，不靠无关静物或营销模块制造特色 |

各类页面强调不同能力，不强迫所有界面用同一种表现：

- 品牌官网：主视觉与文字有明确关系，跨区块节奏变化，完整页面延续品牌。
- 后台与工作台：主分析、辅助指标、待办和记录有不同分量；通过信息编排、字体、图表与组件细节形成辨识度。任务本来需要大表格时，精确设计表格，不为求新颖牺牲扫描和批量操作。
- 移动产品：内容、操作与导航比例适当，小空间里的字体、图像和状态细节自成体系，主操作不被品牌区挤走。
- 游戏界面：世界观通过素材与视觉规则进入界面，任务、数值和控件仍清楚；不能把全部主题表达都删掉，也不能让装饰吞掉操作区。

验收分开判断视觉质量与业务/实现质量。两者都满足才通过；内容正确不能抵消平庸，图片惊艳不能抵消错误状态和不可用操作。与选定参考和上一版实际对照，指出改进证据，不把自己的偏好包装为客观行业评级。

## 先把页面设计清楚

先判断用户的浏览与操作顺序，再选择布局。展示数据用表格或图表，反复浏览同类对象用稳定列表，需要比较的对象才用并列卡片。每个区域承担明确用途，不为了填画布添加指标、徽章或装饰模块。

## 在组件参数之前确定视觉构思

业务清单决定内容是否完整，不能直接决定页面长什么样。对需要品牌表达的页面，先在文字或简短布局草图中比较两个有实质差异的方向，选择与内容最匹配的一种再生图；不强制多轮提问或额外生成候选图。若用户已有明确方向就沿用。

每个方向要回答：访客先注意什么，品牌为什么这样呈现，以及这个选择如何贯穿页面。用具体的构图、文字形态、照片视角、比例对比或色彩关系表达，不能只有“高级、温暖、专业”。挑选一个主要视觉手法，让其他部分配合，不同时堆叠多种抢眼效果。参考图的字体气质要拆成字形、字重、比例与间距，不把英文字体类别直接翻译为中文宋体或手写字。行业或体验类比主要指导组织与表达；若模型把“生活方式”“杂志”等词变成无关静物和口号，应移除歧义诱因，不能继续堆叠修饰词。

允许有明确目的的大胆设计：文字与大尺度主视觉形成张力、适度错位与重叠、特殊裁切、强弱区域和留白的变化。为这些表现选择稳定实现方式，如Grid、字体、SVG遮罩、独立透明素材和可解释的定位；能由这些方式可靠实现的设计，不应仅因超出普通卡片布局而被删掉。

操作密集页面的特色可以来自紧凑的信息编排和恰当的组件细节，不要求后台、结算页也采用品牌展示页的戏剧化构图。效率是设计需要解决的问题，不能成为省略视觉构思的理由。后台先确定用户此刻的核心判断与行动，让主分析、辅助指标、待办与记录拥有不同分量；再选择适合产品的字体、留白、色面与图表表达。不能把“侧栏＋四张指标卡＋折线＋表格”作为默认设计答案，也不必为了避开模板禁用这些合理组件。卡片只在信息归组需要时使用，重要信息也可以直接排版。反过来，品牌网站不能只凭信息完整、控件规整就通过设计验收。

在任务目录保留简短设计说明，与图片一起交付。小任务可写在回复中，不强制创建多份配置：

| 内容 | 需要确定的决定 |
| --- | --- |
| 目标与范围 | 用户任务、主操作、单屏还是完整滚动页面、必须出现的区块 |
| 视觉构思 | 主要视觉手法、第一眼的焦点、与业务/品牌的关系，以及跨区块如何延续 |
| 逻辑视口 | 目标设备的 CSS 宽高、滚动方向、固定导航或底栏、安全区域 |
| 结构 | 内容顺序、主次区域、对齐基准、重复组件及其数据 |
| 设计规则 | 字体及可用来源、字号层级、间距尺度、圆角、颜色和阴影 |
| 素材 | 照片/插画用途、容器宽高比、裁切方式、与正文的边界 |
| 变化 | 窄屏如何重排、标题变长如何换行、列表增加如何滚动、关键状态如何显示 |

先复用已有设计系统。没有时选择少量自洽的规则，例如以4或8为基准的间距、一个正文家族与可选品牌标题字体、少量字号和圆角。它们是可调整的默认选择，不是所有产品必须相同的样式。字体没有可用文件或合法来源时，指定现实可用的替代，不能依赖模型生成的独特字形。

区分三个量：逻辑视口是一次看到的浏览区域，文档高度是全部滚动内容的长度，生成像素是图片分辨率。例如移动端逻辑视口390×844，控件和字体按这一尺度设计；生成像素更大时等比映射，不把生图的1024像素宽当成手机布局宽。桌面长页可以有数千像素文档高度，但这不是桌面视口高度。实际输出比例不匹配时如实标注；不可拉伸，也不能硬塞内容或用极小文字掩盖问题。

写提示词前做一次内容与空间自检：进度分母与任务总数、金额与数量、日期与星期是否一致；按组件尺寸估算指定内容能否出现在目标视口中。放不下时明确哪些内容在首屏、哪些需要滚动，或改用更紧凑布局，不能同时要求全部展示和不改变尺度。示例文案同样需要这一步。

## 让视觉特色服务内容

“干净”意味着文字、图像与控件有清楚的职责和边界，重复元素遵守同一规则，不等于必须白底或没有个性。

- 产品界面默认使用清晰的色面、真实可用字体、一致图标和克制的分隔。照片放进明确容器，不能将搜索框、正文或导航融进照片里。
- 品牌落地页围绕选定构思组织文字、图片和区域节奏。强标题、非对称布局、大图、鲜明配色和适度重叠都是可选手段，不能把它们再固化为另一套必用模板。重叠应能说明定位与窄屏处理，不靠整页任意绝对定位维持。
- 游戏界面可以保留主题插画、配色、图标或可复用边框素材，但任务、背包、数值、按钮仍遵守可读与可操作规则。不要把“容易还原”理解为去掉所有游戏特色。
- 纸纹、颗粒、光晕、手写标注和撕纸边只在明确风格需要时使用，限制在有理由的区域。它们不能作为“提升设计感”的默认补丁。

主操作应醒目，次操作有区分；选中、禁用、完成和错误状态有可解释的视觉差异。颜色不独自承担状态含义。控件不能因为画面精美而缩到难以点击，正文也不能为了塞满单屏而缩小。

## 提示词结构

设计说明负责完整性与可实现性，生图提示词负责激发并约束当前画面。不要把说明全文转录成图片任务；每个区块的固定列数、坐标、字号和间距全部写死，会把探索变成模板填空。

| 当前任务 | 提示词主线 | 留给模型的空间 |
| --- | --- | --- |
| 新品牌与视觉探索 | 一个与内容相关的类比/概念，加少量字体、色彩或摄影方向，再给必需内容 | 自行决定构图、比例、区域节奏与视觉关联 |
| 订单、分析等密集业务界面 | 核心任务、内容关系、真实示例数据与组件约束 | 在不破坏效率的前提下探索信息编排和视觉细节 |
| 已有设计延展或还原 | 参考图、必须保留与允许变化的区域 | 在指定区域内探索，不重设计已锁定的部分 |

类比的作用是激活另一种组织与表达思路，例如“像音乐工作台一样整理创作者的内容信号”。它是值得尝试的提示方法，不是已证明在任何模型上都更优的定律。选择一个主概念，不把多种品牌名、风格名和“顶尖、获奖、高级”等评价词堆在一起。

以正面描述想看到的效果为主，只保留与本任务失败风险直接相关的限制。若连续输出仍是模板布局，先检查参考是否真正传入、类比是否误导、内容清单是否提前锁死结构，不继续只改颜色和审美形容词。用户明确进行视觉探索时，可先用关键内容验证方向；必须标明省略项，方向成立后补齐完整需求并重新检查，不能把探索图冒充最终完整设计。探索阶段先不锁定每个区块的构图；方向成立后，再针对实际问题补精确约束。每次微调指出一个主要问题、保留哪些有效部分，以及这次只改变什么。修改后同时比较解决了什么问题、损失了什么特色；不能只因为更整齐就判定更好。把可验证的阅读、内容、状态或布局缺陷与审美偏好分开：斜切、手写标记、夸张比例本身不是缺陷，只要服务于构思且实现边界清楚就可保留。用户选定的视觉特色应成为后续迭代的保留项。用户授权自行评估时可以据此迭代，仍需保留版本和如实报告主观判断。

下面是可选信息骨架，不要求逐项填满。必要文案必须准确，其余内容只传当前画面需要的信息：

```text
设计对象与用户任务：[用户在什么设备上做什么，核心操作是什么]。
范围：[单屏/滚动页面/完整长页]；逻辑视口：[宽高]；输出画布：[像素或比例]。
视觉构思：[主要视觉手法、第一眼焦点、与品牌/任务的关系]。
内容顺序：[区域与主要组件，真实或明确标注为示例的数据]。
设计规则：[可用字体、字号层级、间距、配色、控件一致性]。
素材边界：[照片/插画放在哪里，哪些内容必须是可编辑组件]。
适配行为：[长文本、更多列表项、窄屏与固定区域的处理]。
必须原样出现的文案：[必要标题、按钮、标签与数值]。
```

只传当前画面需要呈现的信息。隐藏交互的说明保留在设计说明中，不要求模型把所有状态同时画进页面。栅格设计稿中的文字仍是像素；“可编辑组件”指后续实现的分工，不代表生图工具输出了可编辑图层。完整长页用完整长页流程组织区块，不能将这份结构变成一段无限增长的提示词。

## 多状态与多屏一致性

先列出关键状态及相邻状态之间的用户动作、数据变化和控件状态。保持导航、字体、镜头、固定地标和重复组件不变；每张只改变这一步需要变化的内容。奖励、计数与进度从同一份状态记录推导，错误或取消操作不得提前更新结果。

- 九宫格等多屏总览用于看流程：先确认每格按目标展示尺寸仍能读清文字，不默认越多格越完整。逐格核对状态、数量和下一步操作；总览图不能代替可运行原型。
- 单张延展用于看细节与一致性：先检查基础图，再从同一基准生成不同状态；只有确实要测试连续编辑时才串联上一张结果，并记录累积变化。
- 编辑对比用于比较模型：双方使用同一参考文件、提示词、尺寸和质量参数。共享基准即使由某个模型生成，也要单独标明来源，不能算作其他模型的生成结果。

检查时把风格保留与状态正确分开：背景相似不能抵消错数值，数值正确也不能抵消布局漂移。不要为了修正模型对比样本而只重画其中一方；保留首轮原图和明确错误。

## 素材与代码的判断

判断依据是内容能否变化、是否需要交互，以及实现是否稳定，不能仅凭视觉复杂就决定贴图。

- 代码：排版、正文、按钮、输入、列表、表格、常规图标、需要精确或动态数据的图表/地图/关系图。优先已有组件和图表库。
- 素材：摄影、原创插画、品牌视觉和确有必要的复杂装饰。优先原始高质量文件，不为流程默认再生成一次。
- 组合：图片作为独立背景或配图，正文、数据标签和控件仍由代码叠放；说明裁切范围与响应式位置。

若只能把整块页面截图当背景才能“还原”，返回检查布局和素材划分。只有用户明确要求原样复刻现有设计时，才保留其特殊表现并说明代价，不能悄悄把原设计清洗成另一套风格。

## 生成后的检查顺序

| 检查 | 实际查看什么 | 未通过怎么处理 |
| --- | --- | --- |
| 范围 | 单屏与滚动边界；长页区块是否齐全、顺序是否正确、是否到页脚 | 补缺失区域，不能把首屏称为完整网站 |
| 内容 | 文案、数量、金额、日期、状态、图表数值与箭头方向；现有产品对照材料核验功能，排除模型擅自补出的角色、承诺或能力 | 修正对应区域；模型对比保留错误并记录 |
| 视觉构思 | 选定的焦点与表达是否可见；品牌页是否只是换了品牌名和图片的通用模板 | 回到构图、排版和素材方向调整，不靠加纹理装饰救场；最终审美由用户判断 |
| 层级 | 第一眼能否找到核心信息与下一步操作；标题是否挤占工作区 | 调整区域分配和字号，而非增加装饰 |
| 一致性 | 同类按钮、卡片、行高、图标线宽和对齐是否统一 | 统一组件规则 |
| 可读性 | 按目标逻辑视口查看正文、标签、触控区域和对比度 | 修正字号、布局或允许合理滚动 |
| 素材边界 | 文字和控件是否被烘焙在图片中；纹理是否侵入阅读区域 | 拆分素材或简化视觉处理 |
| 可实现性 | 是否能指出组件与布局方式；长标题、加一条数据、窄屏时是否合理 | 修复结构或记录待验证的实现限制 |

图片审核可以发现明显问题，但无法证明实际交互和响应式已经正常。没有代码实测时，将这些判断标为设计检查；还原后再验证真实行为。
